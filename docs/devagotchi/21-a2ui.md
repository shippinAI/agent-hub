# 21. A2UI surfaces rendered with React Aria Components

[Index](../devagotchi-spec.md) · Research 2026-10-18 against the A2UI repo (github.com/google/A2UI, commit
`cbaa5ee`, 2026-10-17) and [a2ui.org](https://a2ui.org/). React Aria Components only; no shadcn, no Radix.

## Current state of the protocol

| Version | Status (per a2ui.org) | What matters to us |
|---|---|---|
| v0.9.1 | **Current** production release; MIME `application/a2ui+json` | Build against this |
| v1.0 | **Release candidate** | Plan the migration; do not ship on it yet |
| v0.8 | Legacy | Ignore |
A2UI is Apache 2.0, created by Google with CopilotKit and community contributors ([a2ui.org](https://a2ui.org/)).

**Event model (v0.9)** ([protocol](https://github.com/google/A2UI/blob/main/specification/v0_9/docs/a2ui_protocol.md)):
- Agent → renderer, one key per message: `createSurface {surfaceId, catalogId, theme?, sendDataModel?}`,
  `updateComponents {surfaceId, components[]}` (flat adjacency list, one component has id `root`),
  `updateDataModel {surfaceId, path (JSON Pointer), value}` (omitting `value` deletes), `deleteSurface`.
- Renderer → agent: `action {name, surfaceId, sourceComponentId, timestamp, context}` and `error` (standard
  `VALIDATION_FAILED` with `path`). With `sendDataModel`, the full surface data model rides in transport metadata.
- Bindings: any `Dynamic*` property is a literal, a `{path}` or a function call; `formatString` interpolates
  `${/json/pointer}`. Local actions call client functions instead of the agent.
- Transport must keep order and framing (JSONL, SSE, WebSocket); MCP tool outputs or resource subscriptions are
  listed as a carrier.
- Basic catalog components: Text, Image, Icon, Video, AudioPlayer, Row, Column, List, Card, Tabs, Divider,
  **Modal**, Button, CheckBox, TextField, DateTimeInput, ChoicePicker, Slider. There is **no Tooltip or Popover**.
- Identity: the orchestrator should overwrite `agentDisplayName`/`iconUrl` with the verified agent identity.

**v1.0 changes** ([evolution guide](https://github.com/google/A2UI/blob/main/specification/v1_0/docs/evolution_guide.md)):
`callRendererFunction`/`callAgentFunction` RPC with `allowedCallers` and `requiresUserActivation` (`openUrl` needs a user
gesture); mixed catalogs per surface; `theme` removed; `@path`/`@call` prefixes (do not blind find-and-replace);
"client/server" renamed "renderer/agent"; `AccessibilityAttributes {label, description, live, hidden}` that
renderers MUST map to ARIA, with explicit labels overriding inferred ones; catalog `allowedParents/allowedChildren`.

Renderers: an official React package exists (`@a2ui/react`, latest 0.14.0 on npm, with `@a2ui/web_core`)
([source](https://github.com/a2ui-project/a2ui/tree/main/typescript/renderers/react), [npm](https://registry.npmjs.org/@a2ui/react)).
Whether it lets us replace every widget with our own components is **unverified**.

## Our design (inference)

**Catalog `https://devagotchi.com/a2ui/catalog/v1`** (JSON Schema with `$id` = `catalogId`, per spec):
the basic catalog's layout and input components, plus `Tooltip`, `Popover`, `Modal`, `AlertDialog`, `Table`,
`Badge`, `Meter`, `ProviderChip` (icon + label for a provider/model, used by Chatmaton tabs, [24](24-chatmaton-spec.md)).
Every child reference uses `ComponentId`/`ChildList` so validators can check the tree.

| A2UI component | React Aria Components | A11y rule we enforce |
|---|---|---|
| `Tooltip {trigger, text}` | `TooltipTrigger` + `Tooltip` on a focusable trigger | Text only, no interactive content; shown on hover **and** focus, Escape closes, pointer can move onto it (WCAG 1.4.13, [APG tooltip](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/), [1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus)). Not shown on touch ([RAC Tooltip](https://react-aria.adobe.com/Tooltip)), so the same info must exist elsewhere |
| `Popover {trigger, title, child}` | `DialogTrigger` + `Popover` + `Dialog` | Non-modal; must have a title or `accessibility.label`; may hold controls ([RAC Popover](https://react-aria.adobe.com/Popover)) |
| `Modal {trigger, title, child, dismissable}` | `DialogTrigger` + `Modal` + `Dialog` (`Heading slot="title"`) | Focus trapped and restored; title required ([RAC Modal](https://react-aria.adobe.com/Modal), [APG dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/dialog/)) |
| `AlertDialog` | `Dialog role="alertdialog"` in `Modal` | Used for risk confirmations; never agent-dismissed |
| `Button`, `TextField`, `CheckBox`, `ChoicePicker`, `Slider`, `Tabs`, `List` | `Button`, `TextField`, `Checkbox`, `RadioGroup`/`Select`/`CheckboxGroup`, `Slider`, `Tabs`, `GridList` | Visible label or `accessibility.label`; lint refuses an interactive component with neither (v1.0 rule, applied early) |

**Data from AI or DB.** The hub is the A2UI *agent* for its own surfaces. Two sources feed `updateDataModel`:
1. An AI writes values (e.g. a tooltip explaining a risk): the hub validates against the catalog, then forwards.
2. A **binding** (data row) maps a surface path to a hub query: `{surface: "grant-card", path: "/grant",
   source: "query:grant_by_id", params: {"id": "${/grantId}"}, refresh: "sse:grant.*"}`. The hub runs the query
   under the viewer's permissions and pushes updates when the matching SSE event arrives. Agents never get SQL.

**Transport.** Over the existing SSE stream (`/stream`, event type `a2ui`) for the web UI; for MCP clients, as an
MCP Apps resource that hosts our renderer ([18](18-public-product-research.md)) (**inference**: one renderer, two
carriers).

**Safety.**
- Only catalog components render; unknown components show a placeholder and an `error` goes back.
- `action` events become hub calls only through a mapping table (data: action name → hub op + required role +
  policy check). A surface cannot call a tool the viewer could not call by hand.
- URLs (`Image`, `openUrl`) must pass the same host allowlist as `net.fetch`; `openUrl` needs a user gesture.
- Text is rendered as plain text or our sanitized Markdown, never HTML.
- `agentDisplayName`/`iconUrl` are set by the hub from the principal record, never taken from the agent.

**Renderer choice.** Parse and validate with the A2UI JSON Schemas; keep the component map (A2UI type → RAC
component) in `web/src/a2ui/` as one file per component (no barrel file). Use `@a2ui/web_core`'s message processor if
it lets us supply our own components; otherwise write a small processor (surfaces map, adjacency list, JSON Pointer
store). Decide after a spike ([28](28-public-gaps-and-phases.md)).

**Tests.** Golden JSONL streams → rendered DOM snapshots; axe checks; keyboard paths (Tab, Escape, Enter) for each
overlay; out-of-order component messages (root last) render once root arrives.
