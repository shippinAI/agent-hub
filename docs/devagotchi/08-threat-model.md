# 8. Threat model
[Index](../devagotchi-spec.md) · Assets: user files, processes, and the desktop (screen contents and input) on enrolled machines, guide content integrity, provider secrets, subscription logins, the integrity of the task board and audit log, and tenant isolation (cloud). Trust: humans with UI auth > hub > bridge > agents (agents are **untrusted**, including the text they put in `reason`).

| # | Threat | Mitigation | Residual |
|---|---|---|---|
| T1 | Prompt-injected agent tries to escape scope (paths, `sh -c`, `<()`, symlinks, case folding) | The OS sandbox enforces the selector. Argv only, no parsing. realpath on the bridge. Grants built from the hub row, not from call args ([#791](https://github.com/wonderwhy-er/DesktopCommanderMCP/issues/791), [#497](https://github.com/wonderwhy-er/DesktopCommanderMCP/issues/497), [#730](https://github.com/wonderwhy-er/DesktopCommanderMCP/issues/730)) | Sandbox bugs; `unsandboxed` grants when the operator enabled the policy (D1) |
| T2 | Agent grants itself more access | No MCP tool writes grants. Human-only approval in code. No self-approval. No bridge config tool | A compromised human UI session |
| T3 | Social engineering via a persuasive `reason` | Reason labelled "the agent says". Risks come from the catalog, not the agent. Narrowing by default suggested. Deny cooldown collapses repeats | User fatigue |
| T4 | Data exfiltration over allowed hosts | `net.egress` default none. Broad-domain risk rows. Proxy limit (no TLS inspection) stated ([Claude sandboxing](https://code.claude.com/docs/en/sandboxing)) | Domain fronting through an allowed host |
| T5 | Stolen machine token | Token 0600/ACL. Per-machine HMAC on calls. Revoke from the UI. Token only lets the bridge *receive* calls, not issue them | A local attacker with user rights can run as the bridge |
| T6 | Compromised hub sends malicious calls | The bridge executes only under a grant it re-fetches. Calls are signed. The sandbox still applies. **Inference:** a hub compromise equals the union of live grants, so short durations and `task` grants limit the blast radius | Full compromise within live grants |
| T7 | Revocation lag | Revoke push + `grant_cache_seconds` ≤30 (code clamp). Running calls under the grant are killed | ≤30 s window if push fails |
| T8 | Stale/orphan process keeps running | proc leases with fence + TTL. The reaper kills the tree (job object / process group / cgroup) | Daemonised children that double-fork out of the group on Linux without cgroups |
| T9 | Edit clobbers concurrent change / partial write | `expect_sha256`, temp+fsync+rename, exact match ([#433](https://github.com/wonderwhy-er/DesktopCommanderMCP/issues/433), [#97](https://github.com/wonderwhy-er/DesktopCommanderMCP/issues/97)) | Non-atomic network filesystems |
| T10 | Secret leakage (logs, events, MCP, UI, screenshots) | Write-only secrets, `fp` only, redaction patterns in bridge logs, output bodies never in events, no "show" toggle | Secrets printed by the user's own commands into exec output (shown only to the caller) |
| T11 | Subscription credential misuse / ToS breach | No proxying of subscription tokens. `client_login` only inside the official client, on the user's device or in their own isolated hosted workspace; the hub never reads client homes ([34](34-provider-schema.md)) ([Anthropic terms](https://code.claude.com/docs/en/legal-and-compliance)) | Vendor terms change (shown as plain `terms_note`); a hosted workspace is compromised (per-user volume, no cross-tenant mounts) |
| T12 | Telemetry / supply chain | No telemetry. Signed pinned binaries. No auto-update without consent. Reproducible builds (goal) ([#797](https://github.com/wonderwhy-er/DesktopCommanderMCP/issues/797), [#327](https://github.com/wonderwhy-er/DesktopCommanderMCP/issues/327)) | Compromised signing key |
| T13 | Cross-tenant access (cloud) | `tenant_id` on every row + Postgres RLS. Tenant derived from the credential. Per-tenant data keys | RLS policy bugs (tests required) |
| T14 | Audit tampering | Existing append-only triggers + hash chain + verify endpoint. New events use the same writer | A DB superuser can rewrite and re-hash; export anchors are decision D11 |
| T15 | Presence spoofing / false "online" | Online only after an executed call result | None material |
| T16 | Enrollment code interception | 10 min, single use, hashed, 5 tries, entered at a prompt not argv | Shoulder-surfing |
| T17 | Phishing via MCP elicitation | Elicitation never asks for secrets. The hub card is canonical (MCP elicitation rule) | Client UI that hides the requesting server |
| T18 | Prompt injection through what is on screen (web pages, emails, images) steering GUI actions | Screen content is untrusted input. Consequential actions (purchases, sending, accepting terms, deleting) need a human confirm step; app/window allowlist; per-minute action cap. Precaution list from [Anthropic computer use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool) | Injection the operator also misses |
| T19 | GUI escapes the exec/fs sandbox (agent opens a terminal or file manager by clicking) | `gui.input` selector allowlists apps/windows; helper checks the foreground target before each action and refuses others (`gui_target_not_allowed`); risk row says plainly that GUI is not sandboxed. **Inference:** this check is in user space, not kernel-enforced | A permitted app that can itself launch others (browsers, IDEs) |
| T20 | Secrets captured in screenshots (password managers, 2FA codes, chats) | Default `gui_screenshot_retention=none`: images go only to the calling agent and are not stored; events hold hash + size. Thumbnails, if enabled, are redacted and encrypted with an expiry. `gui.observe` risk row names this | The agent's own provider sees the image it was sent |
| T21 | Input to elevated or secure UI (UAC prompts, login, admin dialogs) | No `uiAccess` on Windows (UIPI then blocks injecting into higher-integrity windows, [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput), [UIAccess](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview)); the helper refuses secure desktops; elevated steps are operator steps in guides | Note: SendInput gives no error on a UIPI block, so the helper verifies by re-reading state |
| T22 | X11 gives any client full capture and input with no OS prompt | The OS cannot gate it, so the bridge's grant check is the only gate; X11 GUI grants carry an extra risk row; prefer Wayland portals where available | Other local X clients are equally capable (not ours to fix) |
| T23 | Tampered or malicious guide content (a step that tells the operator to run a harmful command) | Shippin bundles are signed and verified on import; tenant edits need `guide.edit`; publish needs a human; every version is immutable and diffable; steps cannot grant access; commands shown are also checked against the grant at run time | A compromised Shippin signing key or a careless admin edit |
| T24 | Docker group or daemon gives root-equivalent access | Docker guide prefers rootless Docker or Podman on Linux; adding the user to `docker` shows the "root-level privileges" risk ([Docker post-install](https://docs.docker.com/engine/install/linux-postinstall/)); the bridge's exec grant for `docker` is its own high-risk capability selector | Operator chooses the docker group anyway |
| T25 | Published container ports bypass ufw/firewalld | Docker guide shows the warning ([Docker on Ubuntu](https://docs.docker.com/engine/install/ubuntu/)) and suggests binding to 127.0.0.1 | Operator ignores it |
| T26 | Full-access default becomes normal and forgotten | Alert on every session resume (01 invariant 7), persistent banner and header marker, `resume_acks` audit, policy expiry option | Alert fatigue |
| T27 | Stolen Wayland restore token re-opens screen/input without a prompt | Token single-use and stored 0600 on the machine only, never sent to the hub ([RemoteDesktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html)); revoking GUI on the machine deletes it | Local attacker with the user's rights |

## Out of scope (v0.1)
Physical access to an unlocked machine; a malicious user attacking their own machine; kernel sandbox zero-days; vendor model providers' handling of screenshots sent to them (covered by their own terms).
