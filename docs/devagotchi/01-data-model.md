# 1. Data model
[Index](../devagotchi-spec.md) · Extends the tables in [spec.md](../spec.md#data-model-postgres). Every new table has `version bigint` (optimistic concurrency, `If-Match`) and every write appends to `events` in the same transaction (hash chain unchanged).

## Data vs code
**Data (UI-editable, preset-seeded):** machines, shell profiles, capabilities, risks, risk-to-capability links, grant presets, grant duration options, the unsandboxed policy, guides and their versions, providers, router endpoints, subscriptions, role bindings, tenants, plan limits, and settings below. Policies gain new action names (`machine.*`, `grant.*`, `exec`, `fs.*`, `gui.*`, `guide.*`, `subscription.*`); those names are data rows in `capabilities`.
**Code (invariants only):**
1. Only a **human** principal may approve, narrow, or revoke a grant, enable the unsandboxed policy, or publish a guide version, and never for their own agent token (same rule as "nobody edits their own roles"). No MCP tool writes `grants`, `grant_presets`, `guides`, or the unsandboxed policy.
2. Deny wins: deny policy > grant > nothing (deny-by-default). Order: deny, then ask, then allow ([Claude Code permissions](https://code.claude.com/docs/en/permissions)).
3. The bridge rechecks the grant on every call (it does not cache allow decisions longer than `grant_cache_seconds`, max 30, as a code clamp).
4. Secrets are write-only: stored encrypted, never returned by any API, and logged only as `fp` (first 8 hex of SHA-256).
5. A machine's presence is set only by a completed executed call (see 03).
6. Edits require an expected hash; writes are temp+fsync+rename.
7. A grant at sandbox level `unsandboxed`, or any live grant created from a preset with `full_access=true`, shows a blocking alert on **every** session resume and a persistent reminder while live. This cannot be turned off by data; only the wording is data (decisions D1, D4).
8. GUI input is never sent to an elevated or secure desktop, and the GUI helper never requests Windows `uiAccess` (see [11](11-gui-control.md)).
9. A guide step can never create or widen a grant. Steps that need access call `request_access` like any agent (see [12](12-guides.md)).

## New tables
- `machines(id text pk, tenant_id, principal_id → principals (kind machine), label, os text, kind native|wsl|vm, host_machine_id null → machines, arch, bridge_version, sandbox_kind text, display_server text null (x11|wayland|quartz|win32), gui_ready jsonb (per-permission state, see 11), shell_profile_ids text[], enrolled_by, enrolled_at, last_exec_ok_at null, last_exec_err_at null, last_error text null, connected bool, disabled bool, version)`. `connected` = socket up; **online** is derived = `last_exec_ok_at > now() - online_window_seconds`. A WSL distro is its own row with `kind=wsl`, `os=linux`, and `host_machine_id` set to the Windows machine (D2).
- `shell_profiles(id text pk, os, label, argv_prefix jsonb, env_allow text[], cwd_default, pty bool, version)`. Presets: `bash` `["/bin/bash","-lc"]`, `zsh`, `pwsh` `["pwsh","-NoProfile","-Command"]`, `cmd`, `direct` (no shell, argv runs as given; the default). Fixes DC shell drift ([#4](https://github.com/wonderwhy-er/DesktopCommanderMCP/issues/4), [#443](https://github.com/wonderwhy-er/DesktopCommanderMCP/issues/443)).
- `capabilities(id text pk, label, description, selector_schema jsonb, sandbox_levels text[], default_duration, version)`. Presets: `fs.read`, `fs.write`, `exec`, `proc.interactive`, `net.egress`, `gui.observe`, `gui.input`, `gui.window`, `gui.app` (see [11](11-gui-control.md#grant-scopes)).
- `risks(id text pk, title, plain_text, severity low|med|high, mitigation, source_url null, version)` and `capability_risks(capability_id, risk_id, when_selector jsonb)`; e.g. `net.egress` to a broad domain → risk "data can leave via that site" ([Claude sandboxing](https://code.claude.com/docs/en/sandboxing)); `gui.observe` → "the agent can see everything on screen, including passwords and messages".
- `grant_presets(id text pk, tenant_id, label, description, items jsonb ([{capability, selector, sandbox_level}]), duration jsonb, full_access bool, requires_policy text null, is_default bool, version)`. Presets: `task-scoped` (default; duration `task`), `read-only-look`, `docker-setup` (see 13), `gui-assist` (see 11), and `experimental-full-access` (`full_access=true`, all capabilities, `unsandboxed`, `until_revoked`, `requires_policy=unsandboxed`). Exactly one row per tenant has `is_default` (D4).
- `sandbox_policies(tenant_id, machine_id null, unsandboxed_allowed bool, enabled_by, enabled_at, acknowledged_risk_ids text[], expires_at null, version)`. Default: no row, so `unsandboxed` is off. A row with `machine_id` null applies to the whole tenant; a machine row narrows it. Enabling it is a human action with its own risk card and `policy.unsandboxed.enabled` event (D1).
- `access_requests(id uuid, tenant_id, requester principal, task_id null, guide_run_id null, machine_id, capability, selector jsonb, sandbox_level, duration jsonb, preset_id null, reason text, risk_snapshot jsonb, status pending|approved|narrowed|denied|cancelled|expired, decided_by null, decided_at, grant_id null, created_at, expires_at)`.
- `grants(id uuid, tenant_id, principal_id, machine_id, capability, selector jsonb, sandbox_level, preset_id null, full_access bool, task_id null, expires_at null, uses_max null, uses int, approved_by, approved_at, risk_snapshot jsonb, request_id → access_requests, revoked_at null, revoked_by null, revoke_reason, version)`. Ended grants are kept (history); events reference `grant_id`.
- `resume_acks(id uuid, grant_id, principal_id (human), ui_session_id, shown_at, acknowledged_at null, action continue|revoke|pause)`: one row per resume alert (invariant 7).
- `proc_leases(id uuid, machine_id, grant_id, holder principal, task_id null, argv_fp text, pid_hint int, fence bigint (from fence_seq), lease_expires_at, heartbeat_at, state running|exited|killed|lost, exit_code null, started_at, ended_at)`.
- `gui_sessions(id uuid, machine_id, grant_ids uuid[], holder principal, task_id null, display_server, monitors jsonb, fence bigint, lease_expires_at, state starting|active|paused|ended, started_at, ended_at, end_reason)`. One active GUI session per machine (the desktop has one pointer).
- `gui_artifacts(id uuid, gui_session_id, kind screenshot|thumbnail, sha256, width, height, redacted bool, blob_ref null, expires_at null, created_at)`. `blob_ref` is null unless retention keeps the image (setting `gui_screenshot_retention`, decision D15).
- `guides`, `guide_versions`, `guide_runs`, `guide_updates`: see [12](12-guides.md#data). Container runtime presets (`docker_runtime_presets`): see [13](13-docker-setup.md).
- `providers(id text pk, kind api|subscription_cli, label, models jsonb, router_endpoint_id null, cli_name null, terms_url, terms_status verified|unverified, terms_note, version)`.
- `router_endpoints(id text pk, label, url, kind litellm|openrouter|direct, secret_id null, version)`.
- `secrets(id uuid, tenant_id, owner principal, label, ciphertext bytea, fp text, created_at, rotated_at, revoked_at)`; storage choice is decision D5. Wayland portal restore tokens are stored on the machine, not here (see 11).
- `subscriptions(id uuid, tenant_id, owner principal (human), provider_id, label, kind api_key|cli_login, secret_id null, worker_principal_id null, machine_id null, budget jsonb null, enabled, version)`. A `cli_login` row holds **no credential**: it names the machine whose official CLI is logged in.
- `role_bindings(id uuid, tenant_id, owner, role_id → roles, chat_app text, subscription_id, priority int, fallback_subscription_id null, enabled, version)`; e.g. role `reviewer` in chat app `codex` → subscription "Jesse ChatGPT Pro (laptop)".
- `chat_apps(id text pk, label, provider_ids text[], connect_template text, version)`. Presets: `claude`, `codex`, `grok`, `cursor`.
- `tenants(id text pk, name, edition personal|cloud, plan text, version)`. The personal edition has one row `local`; `tenant_id` defaults to it (decision D8).
